title: Twenty addresses is a fixed product limit, not a configurable one
status: active
since: 2026-08-05
affects: [customer]
---

[BR-011](../rules/BR-011.md) caps the address book at twenty. The task that
produced that rule gave the number and nothing else, so three things were
decided here rather than known:

1. **The limit is fixed, not configurable.** No environment variable, no
   per-customer override, no plan tier. If a customer ever needs a different
   limit, that is a knowledge change, not a deployment change.

2. **It applies to every customer equally**, including deleted ones. Deletion
   restricts authentication and nothing else ([BR-003](../rules/BR-003.md)), so
   a deleted customer's address book behaves exactly like anyone else's.

3. **The limit is not retroactive.** Nothing in this system can currently
   produce a customer holding more than twenty, so no migration or grandfather
   clause is specified. If bulk import is ever added, that path has to decide
   what it does about the limit, and this assumption is where it will show up
   as unanswered.

Recorded rather than resolved, because the honest answer is that the person
asking for a twenty-address limit was not asked these questions.
