---
id: BR-011
type: business-rule
title: A customer may hold at most twenty addresses
status: active
since: 2026-08-05
affects: [customer]
implemented_by: [customer]
verified_by: [CT-004]
---

A customer's address book holds at most **twenty** addresses.

Adding an address to a customer who already holds twenty is rejected with HTTP
409. Nothing is created, and the address book is unchanged: the same twenty
addresses, in the same order, with the same default.

The limit counts addresses the customer currently holds. Removing an address
frees a slot immediately, so a customer at the limit can delete one and add
another. Addresses removed in the past do not count, and neither does the
address book of any other customer.

Twenty is a product limit, not a storage one. It exists to keep the address
book navigable rather than to protect the store, so the number is expected to
change by a knowledge delta rather than by configuration
([ASM-001](../assumptions/ASM-001.md)).

The rejection body is the ordinary error shape, `{"message": "..."}`, carrying
a generic message for humans and no machine-readable code, consistent with
every other failure in this module. Unlike the 409 on registration and the 401
on authentication, nothing about this failure is confidential: the caller owns
the address book they are being refused, so the message may say plainly that no
further addresses can be added. It must still not carry a code, a count, or a
remaining-slots figure, because callers would parse them and the wire format
would become the contract instead of this rule.

Editing an address never changes how many exist, so the limit does not apply to
`PATCH`, only to `POST`.

The limit is the last thing checked. An add that names an unknown customer is
404 and an add with a missing or empty line is 400, whether or not the address
book is full, because a request that could never have been stored says nothing
about capacity. Only a request that would otherwise have succeeded gets the
409.

The default-address invariant in [BR-002](BR-002.md) is unaffected. A rejected
add does not touch the default, and a rejected add is not a use of any address,
so it cannot influence promotion.
