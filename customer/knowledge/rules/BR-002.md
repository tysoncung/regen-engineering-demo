id: BR-002
type: business-rule
title: Customer can own multiple addresses with exactly one default
status: active
since: 2026-07-30
affects: [customer, orders]
implemented_by: [customer]
verified_by: [CT-002]
---

A customer may register any number of addresses.

A customer with at least one address has **exactly one** default. A customer
with no addresses has none. That invariant holds at all times, including
midway through any of the operations below:

- The first address added becomes the default.
- Adding further addresses does not change the default.
- Deleting a non-default address does not change the default.
- Deleting the default promotes the **most recently used** remaining address.
  If no remaining address has ever been used, the **oldest** remaining address
  is promoted.
- Deleting the last address leaves the customer with none, and therefore no
  default.

"Used" means the address was the shipping address of an order. Recency is the
order of placement, most recent first. An address becomes used only by placing
an order against it, so there is no separate endpoint for marking one used.

If addresses are added again after the last one was deleted, the rules above
apply from scratch: the next address added becomes the default.

Two addresses may carry an identical line; nothing deduplicates them, and each
is a distinct address with its own identity. Callers that look addresses up by
line rather than id accept the ambiguity themselves.

A customer with no addresses cannot place an order, which is why this rule
affects `orders` as well as `customer`. See
[BR-010](../../../orders/knowledge/rules/BR-010.md).
